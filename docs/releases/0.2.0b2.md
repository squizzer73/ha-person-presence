# Person Presence 0.2.0b2 — what's changed

The main change in this beta is a separate **Dashboard whereabouts** sensor. I wanted the dashboard to remain useful between provider updates, without presenting an old location as a confirmed current one.

## What's new since 0.2.0b1

- **Dashboard whereabouts:** shows the current accepted location, or an explicit **“(last known)”** fallback when current evidence expires. A historical value includes its original observation timestamp so a dashboard card can show its age.
- **History across restarts:** one accepted, settled observation is retained privately per person entry. Restoring it never refreshes its timestamp or asserts current presence. Removing an entry removes its saved history; a mismatched person or remapped source is rejected on restore.
- **No ticking-age recorder writes:** relative age is rendered by the dashboard example rather than written into history repeatedly.
- **Clearer provider guidance:** the README explains iCloud3 in-zone intervals, actual location observation times, Companion App sources and why polling more often may still return an old fix.
- **More regression coverage:** 75 tests cover current versus historical display, timestamp preservation, restore validation, deletion, source remapping, recorder behaviour and the shipped card template, alongside the existing suite.

## What stays the same

**Whereabouts** remains the strict current-location output for automations. Existing person entries, entity IDs, device preferences and user enablement choices are retained. The legacy last-known and observation-time diagnostics keep their previous behaviour.

This release does not change iCloud3 or Companion App settings and does not request extra device locations. The new sensor is additive; existing dashboard cards are not automatically switched to it.

## Upgrading and trying it

Back up first, install 0.2.0b2 and restart Home Assistant. Each person gets one additional enabled Dashboard whereabouts sensor on their existing device page. Use it in display cards; keep current-location automations on the original Whereabouts sensor. See the [dashboard card example](https://github.com/squizzer73/ha-person-presence/blob/main/docs/dashboard-history.md).

History starts empty on the first upgrade and needs an accepted observation before it can be retained. Rejected old provider fixes are not used to seed it. During steady fresh observations, private storage is refreshed periodically; after a crash the restored timestamp can be slightly older, never newer. Normal unload/shutdown saves the latest record.

This is still a beta. Wearing needs a real worn/on-body signal, and watch-only outdoor tracking needs a fresh observation from the carried watch's provider. Physical accuracy and update delays need testing with your devices. Suggestions, bugs and ideas are welcome through the [beta feedback form](https://github.com/squizzer73/ha-person-presence/issues/new?template=beta_feedback.yml).
