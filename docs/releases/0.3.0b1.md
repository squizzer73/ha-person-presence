# Person Presence 0.3.0b1 — family card and travel context

This beta adds a few things I wanted to make the presence information easier to use on dashboards, while keeping the original aim: following the person, rather than a device they have left behind.

## What's changed

- **Family overview card:** see everyone together, with current, last-known and unknown locations clearly labelled. It can show the selected device, distance/direction and optional place description, with a visual editor and mobile layout.
- **Distance and direction from home:** new sensors use accepted, fresh GPS observations from the selected device. Room updates cannot make old GPS current. Switching devices or losing fresh evidence resets movement direction.
- **Optional approximate place descriptions:** connect your own authorized or self-hosted Nominatim-compatible service. This is off by default, with no public endpoint bundled. It uses a bounded private cache, a shared request queue and an administrator cache-clear action. Labels stay separate from tracking decisions.
- **Helpful source suggestions:** existing Person tracker assignments and registry associations suggest sources, showing provider and suggestion basis. You still confirm which sources belong to each device.
- **Separate charging-status timeouts:** iCloud3 defaults allow 30 minutes for wearables and 150 minutes for other devices, or the existing shared limit if longer. Other providers keep the shared signal-age limit. Each device has an automatic/custom option. Wearing, GPS and room limits are unchanged.

## Upgrading

Back up Home Assistant, install the beta, then restart. Existing entries, mappings, entity IDs, user settings and dashboards are preserved. Three sensors are added per person: Distance from home, Travel direction and Place description.

Add **Person Presence** from the dashboard card picker. In storage-mode dashboards its local module resource is registered automatically; YAML resources need the manual URL in the [setup guide](../family-features.md). Refresh the browser after upgrading if needed. Existing dashboards are not rewritten.

Direction starts as Unknown until consecutive usable GPS measurements establish movement. Place description stays Unknown until a suitable service is explicitly configured and enabled. No iCloud account, provider settings or Person tracker assignments are changed by installing this integration.

## Testing and limits

104 Python tests, three Node card tests, lint/format and type checks passed locally. Synthetic seven-person mobile/desktop browser checks cover current/last-known/unknown rows, editor changes and safe text/image handling. An approved household pilot verified the installed code, entities and served card; live browser rendering and physical tracking accuracy remain separate checks.

This is still a beta. Charging status does not prove a watch is worn, and a watch-only trip needs an independent fresh location from its provider. Place lookup sends rounded coordinates to the configured service and its terms apply. The public OSMF endpoint is not supported. No journey archive or historical route map is included.

I'm still using this on my own system and am very much open to suggestions, bugs, changes and ideas. If something doesn't look right, please let me know what you expected, what happened and which providers you use, without posting real coordinates or credentials.
